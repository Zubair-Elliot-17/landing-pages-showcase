## Vision

### 10x Check
The 10x version isn't "10 prettier pages" — it's the project reframing itself as a live, shareable *system*: one link that shows 10 distinct brand worlds, each feeling native to its brand rather than templated, with the navigation itself (transitions, keyboard cycling, dark mode) proving the same "fast + polished" claim the pages are making visually.

### Platonic Ideal
A visitor lands on the gallery, sees 10 clearly distinct brand cards, clicks one and watches it morph into the full page (not a hard navigation), can flip through all 10 with arrow keys, toggle dark mode and watch each brand's palette adapt intelligently, and if they share the link, the social preview card itself already looks designed. The whole thing reads as "one person built this, fast, with taste" — which is exactly the claim being tested.

## Accepted Scope (superseded by the Timebox Pass below — kept here as the original record)
- OG image route per brand page (`app/[slug]/opengraph-image.tsx` or equivalent). Renders the brand name + tagline over the brand's light-mode palette (bg/fg/accent) — always light palette, regardless of the viewer's dark-mode state, to avoid doubling image variants.
- Dark mode: each `BrandPage` config gets a `darkPalette` variant (not just a CSS invert) — resolved below. Toggle lives in the shared nav (visible on gallery and every detail page); persisted to `localStorage`, defaulting to the visitor's OS `prefers-color-scheme` on first visit.
- Framer Motion shared-layout transition (`layoutId`) between gallery cards and detail pages. Fallback: a plain fade-in when there's no `layoutId` match (e.g. a visitor loads `/[slug]` directly via a shared link, bypassing the gallery). Respects `prefers-reduced-motion` — falls back to an instant cut, no animation, when set.
- Global keyboard listener (left/right arrow) cycling `router.push` through the config-ordered brand list.
- README section: "Add a new brand" walkthrough (fork instructions, config shape, image sourcing note) — this is real (if small) documentation work, not a trivial afterthought, sized correctly at Effort S above.

## Outside Voice — Cross-Model Challenge (post-section-review)

An independent Claude subagent (Codex not installed) cold-read this plan and found what the section-by-section review missed by evaluating each addition in isolation:

1. **Core architectural risk (accepted):** a single shared `[slug]` template parameterized only by palette/font/imagery risks reading as "one template re-skinned" rather than 10 genuinely distinct brand pages (Apple/Nike/Airbnb/Spotify differ in layout rhythm and density, not just color). **Resolution: each `BrandPage` config entry now also specifies a `layoutArchetype`** (e.g. `minimal-hero`, `bold-motion`, `photo-grid`, `dark-gradient`) so brands differ structurally, not just cosmetically. This is now the single most important field in the config — it's the fix for the biggest risk to the project's actual premise.
2. **Scope vs. time budget (accepted):** 5 expansions + 13 section-review fixes were each approved individually without checking cumulative cost against the "single sitting" goal. **Resolution: see Timebox Pass below** — real cuts made now that actual available time (a few hours) is known.
3. **Shared-layoutId transition complexity (accepted):** true `layoutId` shared-element animation across a real Next.js App Router route change (not SPA state) is genuinely hard, not a checkbox feature. **Resolution: downgraded to a plain fade/slide transition** — kept the reduced-motion and direct-load-fallback behavior, dropped the shared-element morph.
4. **Aceternity-only-on-showpieces inconsistency (accepted):** 2 pages using Aceternity/Three.js will look categorically different from the other 8. **Resolution: framed explicitly as "hero-tier" treatment** (one line of gallery copy marking which brands get the showpiece treatment) — makes the inconsistency a deliberate design choice, not an unexplained gap.
5. **Missing `next/image` `remotePatterns` config for Unsplash hotlinking** — plain missed technical requirement, not a judgment call. Added directly: `next.config.js` must allowlist the Unsplash image domain or the accepted blur-placeholder feature won't work at all.
6. **No mechanism measures the speed-test itself (accepted):** added a trivial build-time timer — note start time now, note finish time at completion, put "built in X hours" in the README. Directly serves the actual stated goal.

## Timebox Pass (post-outside-voice, user confirmed "a few hours")

Given real available time is a few hours, not unlimited, three of the five original expansions are cut to stretch/fast-follow rather than shipped now:

**KEEP (core premise + essential/trivial, in scope now):**
- 10 pages, each with a distinct `layoutArchetype` (the fix for finding #1 above) + gallery homepage.
- Plain fade/slide page transition (downgraded from shared-layoutId per finding #3), respecting `prefers-reduced-motion`.
- Keyboard arrow-key navigation, debounced against rapid presses, guarded against firing while an interactive element has focus.
- Slug validation before any render work (404 short-circuit for unknown slugs).
- Hero image fallback + `next/image` blur placeholder + `remotePatterns` Unsplash allowlist (finding #5).
- Aceternity reserved for 1-2 hero-tier pages (finding #4), explicitly framed as such; Magic UI elsewhere.
- 44×44px touch target requirement for interactive elements.
- Vercel Analytics (trivial, free tier).
- Build-time timer note for the README (finding #6).
- Lightweight manual QA checklist (not automated tests) covering the flows actually shipped in this pass.

**CUT to stretch/fast-follow (real time cost, not core to "10 distinct pages" or "prove speed"):**
- Per-page OG/social preview image generation.
- Light/dark mode toggle (10 hand-authored dark palettes is genuine content work, not a quick switch).
- OSS-template README reframing ("add a new brand" walkthrough).

## Eng Review Additions (/plan-eng-review)
- **Archetype dispatch:** `[slug]/page.tsx` picks and renders one of `components/archetypes/{MinimalHero,BoldMotion,PhotoGrid,DarkGradient}.tsx` based on `layoutArchetype` — not a single page component with inline conditional branching. Keeps each archetype's markup in one place as they diverge further.
- **Archetype fallback:** an unrecognized/typo'd `layoutArchetype` value in `brands.config.ts` defaults to `minimal-hero` rather than crashing that page — fails safe, consistent with the image and dark-mode-storage fallbacks already in scope. **Not silent:** emits a `console.warn` naming the bad slug + value when the fallback triggers, so a config typo surfaces immediately instead of quietly shipping the least-distinct page.

## Eng Review Outside Voice — Cross-Model Challenge

An independent Claude subagent (Codex not installed) cold-read the plan post-eng-review. Resolved:
1. **Silent archetype fallback (accepted):** see the "Not silent" line above — added a console warning on fallback.
2. **Timebox re-check after eng-review additions:** confirmed the archetype work (4 components + dispatch + fallback) still fits "a few hours" — it's non-negotiable core-premise work, not discretionary polish like the items already cut, so it was correctly kept rather than re-cut.
3. **Over-engineering check:** confirmed the archetype system is justified by the distinctiveness goal alone, independent of the deferred OSS-template idea — kept as designed.

Two plain technical requirements added directly (not judgment calls):
- **SSR compatibility:** Aceternity/Three.js hero-tier components must be loaded via `dynamic(() => import(...), { ssr: false })` in Next.js — Three.js needs `window`, which doesn't exist during server-side rendering; omitting this breaks the build or causes hydration mismatches.
- **Unsplash URL format:** hero image URLs in `brands.config.ts` must be direct CDN URLs (`images.unsplash.com/photo-...`), not page URLs (`unsplash.com/photos/...`) — page URLs are not valid `next/image` `src` values and will fail silently or error.

**Clarification (false-positive check):** the keyboard listener uses **left/right** arrow keys specifically, not up/down — there is no conflict with native vertical page scrolling on taller hero-tier pages. Stated explicitly here since an imprecise summary during the outside-voice pass raised this as a concern.

## Refinement from Landscape Research
Aceternity UI's 3D/particle components pull in Three.js (~600KB before gzip); Magic UI components are <5KB each after tree-shaking. Reserve Aceternity for 1-2 genuine showpiece pages (e.g. the Apple-style hero); use Magic UI for shared/consistent chrome across the rest, to avoid uneven bundle weight across all 10 pages.

## Temporal Interrogation (resolved during review)
- **Dark mode strategy:** each brand config defines an explicit `darkPalette` (bg/fg/accent), not a CSS filter/invert — a naive invert breaks brand-specific hues (e.g. Nike's collateral orange-on-black doesn't come from inverting a white background).
- **Brand identity content (names/taglines/palettes for all 10):** treated as a real content dependency, resolved at implementation Step 1, not deferred past it — see the source design doc at `~/.gstack/projects/zubair/zubair-unknown-design-20260911-074312.md` (Config Schema + Next Steps §1) for the full field list each brand needs (name, tagline, palette, font, heroImage, heroImageAlt, and now darkPalette per the dark-mode item above).
- **OG image route + dynamic `[slug]` interaction:** verify Next.js App Router's `opengraph-image` convention works correctly nested under a dynamic segment before building all 10 — spike this on page 1 (Apple-style) before replicating.
- **Keyboard nav + in-page scroll conflict:** arrow-key navigation must not fire while focus is inside a text input or when the user is mid-scroll-interaction with a component that also binds arrow keys (e.g. a carousel) — scope keyboard nav to only fire when no interactive element has focus.
